# 🍕 Shoh Pizza — Authentication Security Demo

**YF Cybersecurity · 5-dars / Урок 5 · Authentication Amaliyot**

**Shoh Pizza** — учебный сайт пиццерии, разработанный для практического YouTube-урока об уязвимостях аутентификации. Внешне это обычный сервис заказа пиццы, но в локальном режиме в некоторых функциях специально оставлены ошибки безопасности, которые можно сравнить с защищённой реализацией.

> [!WARNING]
> **Только для локального обучения.** Проект намеренно содержит уязвимости в режиме по умолчанию. Все аккаунты, заказы и письма — вымышленные. **Не публикуйте сайт в интернете, не меняйте адрес привязки на \`0.0.0.0\` и не используйте реальные данные.** Тестируйте только собственные или разрешённые учебные системы.

## ✨ Возможности

- Каталог из 6 пицц, корзина и демонстрационные заказы.
- Регистрация сессии после входа и двухэтапная проверка (пароль + учебный код 2FA).
- Личный кабинет с историей заказов.
- Отдельная панель менеджера, защищённая проверкой роли и 2FA.
- Восстановление пароля через локальный тестовый почтовый ящик.
- Два режима одного и того же сайта: **уязвимый** и **защищённый**.
- Наглядное изучение HTTP-ответов в браузере и Burp Suite.

## 🔎 Что демонстрируется

| Тема | Учебный (уязвимый) режим | Защищённый режим \`--secure\` |
| --- | --- | --- |
| Username enumeration | Разные сообщения для неизвестного email и неверного пароля | Унифицированное сообщение |
| Rate limiting | Нет ограничения частоты попыток входа | Ограничение с ответом \`429\` |
| Проверка 2FA | Доступ к **собственным заказам** возможен до завершения 2FA | Доступ только после полной проверки |
| Logout | Серверная сессия не отзывается | Сессия аннулируется |
| Password reset | Разные ответы и повторное использование учебной ссылки | Общий ответ и одноразовый токен |

**Важно:** доступ к панели менеджера требует подтверждённой 2FA даже в учебном режиме. Проверка OTP ограничена количеством попыток. Этот проект **не** является лабораторией SQL Injection.

## 🚀 Запуск

### Kali Linux / Ubuntu / WSL

~~~bash
git clone https://github.com/Solihov-Y/shoh-pizza-authentication-demo.git
cd shoh-pizza-authentication-demo
python3 app.py
~~~

Откройте **http://127.0.0.1:8770** в браузере.

Вместо последней команды можно запустить \`sh START_KALI.sh\`.

### Windows

1. Нажмите **Code → Download ZIP** в GitHub и распакуйте проект.
2. Установите Python 3, если его ещё нет.
3. Запустите \`START_WINDOWS.bat\`, либо выполните:

~~~powershell
python app.py
~~~

Откройте **http://127.0.0.1:8770**.

Не открывайте \`static/index.html\` напрямую — сайту нужен запущенный Python-сервер.

## 🛡 Защищённый режим

Остановите обычный сервер сочетанием **Ctrl + C**, затем запустите:

~~~bash
python3 app.py --secure
~~~

Для параллельного сравнения на другом порту:

~~~bash
python3 app.py --secure --port 8771
~~~

Второй экземпляр откроется по адресу **http://127.0.0.1:8771**. Оба режима используют локальную тестовую базу, поэтому при демонстрациях восстановления пароля и заказов учитывайте изменения данных.

## ♻️ Сброс демонстрационной базы

Остановите сервер и выполните:

~~~bash
python3 init_db.py --reset
~~~

Или запустите \`python3 app.py --reset\` — в этом случае после сброса стартует веб-сервер.

На Windows также доступен \`RESET_DEMO_WINDOWS.bat\`.

> Сброс удаляет все сохранённые тестовые заказы, сессии, письма и изменения паролей. База \`data/shoh_pizza_demo.db\` создаётся автоматически и не включена в GitHub.

## ✅ Локальная проверка

~~~bash
python3 verify_site.py
~~~

Скрипт проверяет основные HTTP-сценарии в учебном и защищённом режимах. Перед запуском убедитесь, что тестовые порты \`8870\` и \`8871\` свободны. Проверка сбрасывает учебную базу.
